`eql-bindings` (the Rust crate released with this package): an EQL v4 type of fixed width whose terms a null has, a storage-only type (`Date`, `Integer`, `Boolean`, ...) or one whose only term is equality's (`DateEq`, `IntegerEq`, ...), now also implements `EncryptFrom` and `DecryptInto` for an `Option` of its plaintext, and its query twin `EncryptFrom` for one. A `None` seals as a typed null as long as a value (vitaminc 0.8), so an optional column does not show which rows are absent, and opens as `None`; its `hm` is the one term every null shares, and the query of a `None` finds the stored nulls with `=`. A value seals exactly as before. The by-name dispatch (`encryption::targets`) reads, opens and queries these types through the `Option`; a type with an order or match term still refuses a null. Text is left out: its ciphertext is as long as the text, so a sealed null would stand out beside the values, and an optional text column stores SQL `NULL` instead. eql-bindings' own `Date`, `Timestamp` and `Decimal` plaintexts declare their fixed width to vitaminc, so their `None` is padded too. The SQL bundle and the TypeScript types do not change.
